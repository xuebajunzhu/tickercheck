## 1. 要验证的假设（可证伪）

| # | 假设 | 证伪条件 |
|---|---|---|
| **H1（主）** | 0 元、零人脉、拒绝熟人、2h/周下，12 周内用**单一**公开渠道让 **≥15 名陌生 A股个人投资者提交真实持仓**（≥3 只 + 成本价 + 仓位） | 累计 <5 份，或 ≥5 份但真实率 <50% |
| H2 | "数据不出本地"是真实决策理由，且本地 CLI 门槛可跨越 | 0 人提及隐私/本地，且 ≥2/3 要求"你跑好发我" |
| H3 | 报告有可感知认知增量，收到者 ≥20% 在 4 周内复检 | 复检率 <5% 且"没有我不知道的东西"≥50% |

**为什么 H1 是主假设**：产品"做不做得出来"已被证实，唯一稀缺资源是**陌生人注意力**。

**两种失败必须分开判**（避免误杀）：曝光低但每份都真实 → 渠道问题，换渠道不换产品；曝光高但提交为 0 → 信任/摩擦问题，走风险 1 替代路径。

## 2. 里程碑与阈值（按周判定，Go / Pivot / Kill）

| 时点 | 判据 | 结论 |
|---|---|---|
| **W4** | `N_stranger ≥5` 且 `Real% ≥60%` | ✅ 进入周期 2 |
| W4 | `N_stranger = 1–4`，真实率 ≥60% | ⚠️ 弱信号：延长周期 1 两周，**只加渠道不加功能** |

| **W8** | 实质回复率 ≥40% 且 `ReCheck% ≥20%` | ✅ 进入周期 3 |
| W8 | 复检率低但认知增量为正 | 🔄 改定位为**节点型需求**（换仓前/年度体检），节奏改季度 |
| W8 | 回复率 <20% 且复检率 <5% | 🔴 **重做报告表达层，不重做引擎**，重跑周期 2 四周 |
| **W12** | 单份 ≤8min 且自发传播 ≥30% 且 ≥3 人愿付代价 | ✅ 进入阶段 07 转化闭环 |
| W12 | 单份 >15min 或自发传播 <10% | 🔄 形态重构：转为可自助下载工具 / 季度开放窗口 |

> 我原定"1 个陌生人索取"降级为**弱信号**（1–4 档），不再作为生死线——单一样本无法区分运气与需求，5 份且真实率 60% 才有最小统计意义。

## 3. 每周 2 小时硬切（不可协商）

| 用途 | 时长 | 说明 |
|---|---|---|
| 分发（公开渠道动作） | **60 min** | 每周 1 次，不做第 2 次 |
| 交付（跑批 + 回传 + 追问） | **50 min** | 按 8 min/份 → 周处理上限约 6 份 |
| 记账 | **10 min** | 周 4 结束后加做 1 次 rollup |
| **新功能开发** | **0 min** | 除阻断性 bug 外一律为 0 |

**周自检**：本周分发时长是否 ≥60min？不是 → 下周先补分发再做任何开发。
新功能想法一律写 `backlog.txt`，12 周后统一处理。

## 4. 明确不做（做了 = 实验必败）

❌ 20 人用户访谈（2h/周做不动，且拿到的是口头答案不是行为）
❌ 建站 / 买域名 / 落地页 A/B（一次性吃掉 6–8h，换来无用的点击率）
❌ 注册 / 登录 / 上传 / 后端 / 邮件服务（撞"需协调第三方 + 实时响应"红线）
❌ 支付与定价实验（H1 未过前谈钱无意义）
❌ 多平台矩阵 / 日更 / 社群（全在"不成立的 7 类业务"清单内）
❌ 托管、留存、展示任何真实持仓数据（合规 + 信任双风险）
❌ **12 周内新增评分引擎功能**（新维度、调优、回测一律不做）

## 5. 三周期动作

**周期1（W1–W4）存在性**：W1 制作 1 份脱敏样本报告 + 登记渠道存量（Q10）+ 定唯一渠道 → W2–W4 每周 1 次公开动作，主体是**样本报告本身**（不写教程、不写行情观点、不做个股评价）→ 提交口只收 CSV 或"3 只代码 + 成本价 + 仓位"文本。

**周期2（W5–W8）价值**：对周期 1 全部提交者交付 → 回传时**只问 1 个开放问题**（"报告里哪一条是你之前没看到的？"）→ 分发降频到每 2 周 1 次，省出时间给交付。

**周期3（W9–W12）可持续**：一次性 2h 固化手动交付（提交模板 + 跑批脚本 + 回传模板，**本周期唯一允许的工程投入**）→ 测单份耗时 → 测非金钱代价意愿（转发/留邮箱/排队，先不真收费）。

## 6. 风险与替代路径

| # | 风险 | 早期信号 | 替代路径 |
|---|---|---|---|
| 🔴 R1 | **信任壁垒**：陌生人不敢交真实持仓（唯一能让 H1 直接归零，且只表现为"没人来"，极易误判为没需求） | 曝光正常但提交 0；或只发 1 只、不发成本价 | **自助优先**：公开工具获取方式，让用户本机跑、**数据永不离开本机、创始人不接触任何数据**。代价是拿不到完整样本 → H1 改判「下载数」而非「提交数」 |
| 🔴 R2 | **合规越界** | 有人问"那我该不该卖" | 一律回"工具不回答这个"；禁评级词/目标价/公开评个股；样本用虚构或指数化（**已执行**）；必附免责 + 数据来源 + 截止日期（**已写进报告页眉**）。被限流 → 后撤到"方法与工具"层，报告仅私发 |
| 🟠 R3 | **时间被开发吃掉**（创始人惯性：12 周都在改引擎，0 小时分发） | 连续 2 周分发 <30min；backlog 周增 >3 条 | 时间盒（§3）+ 新功能只进 backlog + 被占用则**验证周顺延，绝不压缩分发** |

## 7. 只记 3 个数字

正式流水账唯一位置：**`tickercheck/notes/metrics.txt`**（格式与 `06-mvp-design/metrics.txt` 模板一致，不双写）。

- `N_stranger` 陌生真实提交数（亲友/同事/同行/自己小号一律不计；无法判定按无效）
- `Real%` 真实持仓率（≥3 只 + 成本价 + 仓位，缺一判无效）
- `ReCheck%` 复检率（提交 ≥2 次人数 ÷ 总提交人数）

附带：单份端到端耗时（min）、来源渠道、提交者原话摘要。
**口径先写死再开始记**，否则数字会自我美化；历史行只追加更正，不修改。

### 8.1 Q10 = 0 渠道存量下的路径切换（创始人拍板）

用户确认公开渠道存量 = 0。这触发验证设计里的 🔴 R1（信任壁垒）与零渠道困境，于是：

- **主路径由「代跑」切换为「自助优先」**：不再依赖"陌生人提交持仓 → 我跑回传"，
  改为公开开源工具，用户**本机 clone 跑**，数据永不离开其电脑。
- **H1 判据改判**：从「陌生提交数 ≥15」改为「**下载/获取数 + 自愿反馈**」。
- **分发动作 = 开源发布 + 方法论文章**，内容即渠道，不新开粉丝阵地。
- 这把"代跑交付"那条 50min 的时间块重新分配为：注册推送 30min + 发文章 30min。
- **保留弹性**：若有人仍愿意提交持仓换报告（自愿、非诱导），`scripts/batch.py` 仍在，可随时回退到代跑形态。

> 判据变更未动摇 H1 的本质——唯一稀缺资源仍是陌生人注意力，只是获取方式从"收数据"变为"供工具"。
